# V1.0.1 验证总结

## 1. 目标与范围

- 目标：验证普通第三方应用是否可以通过 Intent 打开 MIUI 系统的“定时开关机”页面。
- 版本：`v1.0.1`
- 范围：仅验证“进入页面与基础可操作性”，不包含跨 ROM/跨品牌兼容性承诺。

## 2. 实现路径

- 前端触发：Vue 页面按钮调用 `MiuiPower.openBootShutdownPage()`
- Android 插件：`MiuiPowerPlugin.kt` 按顺序尝试以下入口
  1. `miui.powercenter.intent.action.BOOT_SHUTDOWN_ONTIME`（action）
  2. `com.miui.securitycenter/com.miui.powercenter.bootshutdown.PowerShutdownOnTime`（component）
  3. `miui.intent.action.POWER_MANAGER`（fallback）
- 结果回传：返回 `{ ok, method }`，用于前端状态提示。

## 3. 验证结果

- 首页点击“打开定时开关机页面”后，能够成功跳转到系统页面。
- 页面状态提示为“已尝试打开页面，方式：action”，说明本机优先命中了 action 路径。
- 进入系统页后可见并操作以下项：
  - 定时开机开关
  - 开机时间设置
  - 重复周期设置
  - 定时关机开关
- 时间选择弹窗可正常弹出并确认，说明页面不仅可见且可交互。

## 4. 结论

- `v1.0.1` 已达到预期目标：第三方应用可通过 Intent 进入 MIUI“定时开关机”页面，并完成基础交互验证。

## 5. 已知限制

- MIUI 私有 action/component 在不同版本上可能变更，稳定性依赖 ROM 版本。
- 厂商可能通过导出策略或权限策略限制外部拉起，导致 `method=none`。
- 非 MIUI 设备大概率无法复用该路径。

## 6. 关于“其他界面是否可类似进入”的思考

结论：可以尝试，方法上与本次一致，但成功率取决于目标页面是否存在可导出的 `action` 或 `activity`。

建议沿用同一套策略：

1. 为目标页面准备候选入口（`action` + `component` 列表）。
2. 按优先级顺序尝试，保留统一 fallback。
3. 回传命中路径与失败类型，持续沉淀机型/ROM 兼容矩阵。

建议的验证手段（开发期）：

- `adb shell cmd package query-intent-activities -a <ACTION>`
- `adb shell dumpsys package com.miui.securitycenter`
- `adb logcat | findstr /i \"ActivityTaskManager ActivityManager\"`

如果后续要批量支持多个 MIUI 页面，建议把当前插件抽象为“通用页面跳转器”（传入候选 action/component 队列），避免每个页面重复写一套逻辑。
